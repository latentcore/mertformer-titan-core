## Pre-45K — laptop preflight run-feedback (2026-07-02, real run signal)
Source: `evidence/2026-07-02-laptop-preflight/` (RTX 5070, 8 GB, commit `5fc5068`). The pre-flight validated the infrastructure (atomic checkpoint at step 500; guards live; graceful interrupt-save at step 981) AND produced a decisive negative training-dynamics finding: the run **diverged** (loss ~10.4 → ~15.0; grad_norm → `inf`, sustained `1e11`–`1e16`, survived only via `clip=2.0`; MoE load entropy 0.99 → 0.74). These are the pre-45K stabilization items — **documented as run-feedback; the frozen training path is NOT changed until each is applied and re-verified on a real run:**
- **LR regime:** `1.5e-3` is empirically fatal for this arch at this scale → sweep from `3e-4`, drop the router ×1.5 LR multiplier, lengthen warmup; target clip-hit rate `< 5%` (not "survive despite clip").
- **Liquid spike threshold:** absolute `loss>5.0` is scale-blind (never releases at this loss range → the Liquid layer is effectively untrained). Make it **relative** (`EMA×1.5`) + cooldown.
- **`generate()` Liquid state:** thread the Liquid hidden state through decode (as router state already is) + add a full-forward↔incremental-decode **parity test**.
- **Held-out perplexity harness:** fixed corpus + fixed seed + fixed script (today's eval cannot tell whether a run learned anything beyond its own loss curve).
- **100–300M pilot** before the real 45K (gate: clip-hit `<5%`, no persistent Liquid freeze, no MoE collapse, monotone held-out ppl).

## Pre-45K stabilization — APPLIED as candidate fixes (2026-07-08)
Source: `CLAUDE CODE — AUTONOMOUS EXECUTION BRIEF · Pre-45K Stabilization + Repo Final-Sweep Pass` (rev v2, 2026-07-08). The 2026-07-02 run-feedback items above are now **implemented in code**. They are **candidate fixes pending re-verification on a real GPU run** — nothing below is verified, and the divergence problem is **not** "solved" until a clean RTX-5070 re-run says so.
- **LR regime (T1.1):** `learning_rate` `1.5e-3` → `3e-4` (sweep start, NOT known-good); router ×1.5 differential dropped (`router_lr_multiplier` = 1.0); warmup `0.10` → `warmup_ratio` 0.15. All three sweepable without a commit: `TITAN_LEARNING_RATE`, `TITAN_ROUTER_LR_MULT`, `TITAN_WARMUP_RATIO`. Precision note discovered while implementing: the scheduler's real warmup was `int(max_steps*0.1)` = ~183 steps on that 1830-step run (NOT the `warmup_steps: 3000` echoed into the evidence JSON), so grad_norm began exploding at step ~80 — i.e. **during** warmup, at an effective LR of only ~6.6e-4, well under the 1.5e-3 peak. Treat `3e-4` as unverified.
- **Truth-fix (T1.1):** `warmup_steps` and `min_lr_ratio` were dead fields (`# informational only`) while the scheduler used hardcoded literals. Both are now actually read; `min_lr_ratio` default set to `0.01` so runtime behavior is unchanged (mechanism-only change).
- **Liquid spike threshold (T1.2):** absolute `loss > 5.0` → EMA-relative `loss > loss_ema * 1.5`, with the absolute value retained as a cold-start floor for the first `liquid_spike_ema_warmup_steps` (100) observations. Cold-start-safe EMA reuses `train/continual_adapter.py`'s seed-with-first-loss pattern. The cooldown/patience state machine is unchanged.
- **`generate()` Liquid parity (T1.3):** `MertFormerBlock.forward()` now takes `liquid_state` and returns the mixer's final hidden state (4-tuple); `MertFormer.forward()` threads `liquid_states` per layer and publishes them via `get_last_liquid_states()`; `generate()` carries them across decode steps; `reset_router_state()` clears them. New `tests/test_liquid_generate_parity.py` asserts full-forward ↔ incremental-decode parity **and** carries a negative control proving the old (unthreaded) path diverges.
- **Held-out perplexity harness (T1.4):** new `eval/held_out_ppl.py` — `--ckpt`-mandatory checkpoint-identity tokenizer load (no silent fallback), fixed corpus + fixed seed, deterministic packing via `train/packing.iter_packed_sequences`; writes `reports/benchmarks/held_out_ppl_summary.json` with commit + corpus/checkpoint SHA256 + an explicit claim boundary. Sanity-checked locally: a random-init model scores `mean_nll = 11.7649` against `ln(128000) = 11.7599` — i.e. the harness reproduces the uniform baseline.
- **Stabilization pilot (T1.5):** `config/model/mertformer_pilot_stabilization.yaml` — **measured** 171,617,923 params (via `trainer_core.preflight_param_report()`, not estimated); BitNet + 8e2 MoE + Liquid/CfC + GQA all present; `liquid_warmup_steps` = 667 (= 3000 × 10000/45000, documented arithmetic); runs under GaLore + 8-bit Adam for optimizer parity with the real 45K. **Stabilization-only; carries no capability or scaling claim** — see the STATUS.md reconciliation note.
- **Divergence circuit breaker (T1.6, NEW — not from this backlog):** finite-but-climbing loss now trips `safety_brake_reason = "loss_divergence_relative"` after `divergence_guard_patience` (50) consecutive steps where the loss EMA exceeds `1.5×` the EMA snapshotted at warmup end. Rank-local by construction, so the brake decision is **all-reduced** (mirrors the NaN-brake collective) to avoid DDP desync. `use_divergence_guard` defaults ON; `TITAN_DIVERGENCE_GUARD=0` disables. Logic ported from the inert `orchestrator/failure_budget.py` slope tracker into `utils/divergence_guard.py`, deliberately re-keyed off the loss EMA instead of wall-clock so it is deterministic and testable.
- **WSD scheduler clamp (T1.7):** the decay-phase cosine never clamped `progress` to `[0,1]`. If `TITAN_MAX_STEPS` changes between a checkpoint-saving run and a resume, `progress` can exceed 1 and the LR **rises back toward peak** instead of staying floored at `min_lr_ratio`. One-line clamp + `tests/test_wsd_schedule_clamp.py`.
- **Preflight loss-quality signal (Track 7):** `scripts/preflight_run.py evaluate_verdict()` was infra-only, so the 2026-07-02 divergence produced a clean PASS and a human had to eyeball the curve. It now emits a **non-blocking** warning into `REPORT.md` when `last_loss > first_loss`. PASS/FAIL semantics unchanged (still infra-only, by design).
- **Preflight optimizer parity (Track 7):** `preflight_run.py` no longer forces `use_galore=False, use_8bit_adam=False`. The 45K run uses `GaLoreAdamW8bit`, whose low-rank projection changes the effective step size in ways that do not map 1:1 to plain AdamW — so an LR "verified" under plain AdamW was verifying the wrong optimizer. `build_optimizer()` still degrades gracefully and logs the ACTIVE class.
