# Chess 5080 PoC Internal

This lane is a private operator-facing chess proof flow.

## Entrypoints
- `bash run.sh --chess-5080-poc`
- `bash zero_touch_start.sh --chess-5080-poc`
- `python scripts/chess_5080_onefile.py`
- `python scripts/export_chess_5080_share.py`

## Intent
- Train a standalone chess-only policy/value model on filtered Lichess data.
- Keep legal move masking mandatory.
- Finish on a single RTX 5080 desktop in roughly 1-4 hours.
- Produce a zipped proof bundle with logs, config, provenance, checkpoints, and SHA256.
- Strengthen the training split with an embedded curated opening/tactical/endgame/blunder-correction suite.
- Carry the synthetic Turkish teaching corpus and curated-suite benchmark surfaces in the same onefile envelope.
- Produce a one-click Windows EXE on the delivery lane and collect runtime artifacts under a `runtime/` root.
- Let the Stockfish anchor surface stand up via runtime-side auto-fetch/cache when it's needed.

## Claim Boundary
- `1600+` is a target, not a guaranteed claim.
- Only measured results may be reported as `verified`.
- If Stockfish comparison is unavailable, the run must be marked `target-not-verified` or `not-run`.
- This lane does not upgrade the core 45K repo claim surface by itself.

## Share Export
> **2026-07-27 parity fix:** this section previously described only the legacy open-copy/zip flow; the Windows one-click EXE delivery path (below) had shipped in `scripts/export_chess_5080_share.py` but was documented only in `CHESS_5080_POC_INTERNAL_TR.md`, which had flagged the gap in its own text. Both files now describe the same, current behavior.
- The canonical readable script stays in repo.
- `scripts/export_chess_5080_share.py` generates:
  - open copy
  - Windows build workspace
  - delivery zip
  - SHA256 file
- The share wrapper may self-delete only after a successful packaged run.
- The repo copy must never self-delete.
- The final user-facing artifact is not the source `.py` — it is `external_delivery/mertformer_chess_5080.exe`.
- The final EXE runs under the `delivery_windows_oneclick` profile and uses the runtime Stockfish cache root automatically.
- Runtime artifacts are expected under `runtime/` next to the EXE (not sprayed as new run folders directly onto Desktop); a Stockfish benchmark surface auto-fetches/caches the engine under `runtime/stockfish/` when needed — a manually-placed `stockfish.exe` is not required.
