# Chess 4060 24h Canonical Runbook

## Purpose
Run the frozen chess lane on a single RTX 4060 for the first real 24-hour baseline-supported training pass.

Profile:
- `strength_4060_24h`

Release boundary:
- this is the only 4060 profile that can satisfy the frozen chess release-candidate gate
- `production_5080` remains a supported portable baseline, but not the canonical long-run release path
- `strength_4060_24h_all_on_experimental` and `strength_4060_24h_omni_max` remain research-only

## Canonical Command
```bash
python3 scripts/chess_5080_onefile.py --mode train --profile strength_4060_24h
```

## Optional Supported Variants
Portable baseline:
```bash
python3 scripts/chess_5080_onefile.py --mode train --profile production_5080 --feature-bundle all_stable_extensions
```

Post-run analysis stack on the canonical profile:
```bash
python3 scripts/chess_5080_onefile.py --mode train --profile strength_4060_24h --feature-bundle postrun_analysis_stack
```

## Operator Interpretation Rules
- Repo-side closure does not equal measured strength.
- Self-play, tournament, replay, and proxy-rating outputs stay internal unless separately validated.
- `support_matrix.json` must show `strength_4060_24h` as active and release-candidate eligible.
- `release_gate_summary.json` must keep experimental profiles out of release-candidate eligibility.
- Missing mandatory artifacts are release blockers and must be treated as hard failures for closure.

## Escalation Guidance
- If the run destabilizes, stop and preserve the current artifact root before retrying.
- If the feature report shows unexpected overrides, treat the run as contract drift.
- If `known_limits.json` or `remaining_core_blockers.json` shows a blocker outside the canonical vocabulary, treat that as truth drift and fix the repo before the next run.
