# MertFormer Titan: Training Runbook (Review-Ready)

This document is a **runbook + gated checklist** for starting training. It is written to be reviewable by an external engineering team.

Principles:
- **Offline-first by default** (`TITAN_OFFLINE=1`). Online actions are explicit.
- Separate **Verified (Run)** checks from **Targets/Claims**.
- Treat dataset provenance/licensing as a **P0 gate** before any production training run.

## Baseline
- Python **3.11** (see `repro/python.md`)
- Local venv: `.titan-venv` (created via `scripts/bootstrap_venv.sh`)

## Phase 0: Offline Verification (Must Pass)

Run the offline verify-all pipeline:

```bash
bash scripts/verify_all.sh
```

What this covers:
- Secret scan of tracked files (`scripts/secret_scan.py`)
- Unit/integration tests (`pytest`)
- Preflight (`scripts/titan_preflight.py`, offline-safe)
- Operator gate (safe mode, offline-safe)

Optional: tiny training smoke (CPU/MPS):

```bash
.titan-venv/bin/python scripts/train_smoke.py --cleanup
```

## Phase 0.5: Data Compliance Gate (P0)

Before training:
- `datasets/inventory.md` and `datasets/inventory_TR.md` match code references (generated by `scripts/extract_dataset_refs.py`)
- `datasets/SOURCES*.md` list all datasets referenced by the pipeline and eval
- `datasets/LICENSES*.md` contains **no unknown/TBD licenses** for any dataset intended for training
- `datasets/hashes.json` is filled with snapshot metadata and SHA256 hashes for the **exact** dataset snapshots used (air-gapped compatible)

If any license entries are `TBD` or snapshot hashes are missing, training is **not review-ready**.

Validation data policy:
- For smoke tests, a tiny validation file is acceptable.
- For claim-grade runs, regenerate a representative validation set:

```bash
python3 scripts/build_validation_set.py --target-size 1500
python3 scripts/record_dataset_hashes.py
```

- `TITAN_CLAIM_MODE=1` enforces minimum validation size (`cfg.validation_min_samples_claim`).

## Phase 1: Distillation / Foundation Run (Online, Training Hardware)

Required:
- Training hardware (e.g., multi-GPU Linux host) and a stable CUDA toolchain
- `HF_TOKEN` available (online mode)
- Optional: `WANDB_API_KEY` if experiment tracking is enabled

Recommended execution (explicit online):

```bash
TITAN_OFFLINE=0 TITAN_WANDB=1 TITAN_INSTALL=1 bash run.sh
```

Notes:
- `TITAN_INSTALL=1` is opt-in. For deterministic installs, prefer `scripts/bootstrap_venv.sh` beforehand.
- Logs are written under `logs/` and are **gitignored artifacts**. Treat them as evidence attachments, not commits.

## Phase 2: Agent Integration (Optional / Post-Foundation)

Target work:
- Role-specific adapters (LoRA/PEFT) per agent role (QA, Security, Architect)
- Internal retrieval/memory datasets must follow the same provenance/licensing rules

## Phase 3: Optimization (Optional)

Examples:
- Stability hardening (OOM, NaN drills, checkpoint restore drills)
- Profiling + export validation on the target edge runtime

## Phase 4: Evaluation & Benchmarks (Post-Training)

Internal truth benchmarks:
- HumanEval / MBPP runner: `scripts/benchmarks_internal.py --run`
- Outputs: `reports/benchmarks/*.jsonl`

Behavior:
- If no checkpoint is available, the benchmark runner **SKIPs** and exits 0 (does not break pipelines).

## “Start Training” Checklist (Printable)

- [ ] `bash scripts/verify_all.sh` passes (offline).
- [ ] `datasets/LICENSES*.md` has **no TBD** entries for training datasets.
- [ ] `datasets/hashes.json` snapshot hashes are filled for the exact training data.
- [ ] Claim-grade mode: `datasets/validation.jsonl` is representative and meets minimum sample gate.
- [ ] Training config is pinned and reviewed (seed, dtype, model size, batch settings).
- [ ] Hardware + drivers validated and recorded (attach local notes).
- [ ] Online tokens available in env and verified (without logging values).
